# Changelog

## Unreleased

- **Breaking:** a contact dossier is now one short Markdown document that the model rewrites as the chat goes on, instead of a list of facts with sources. Each refresh sends the current document, the owner note, and the new, edited, and deleted messages; the model returns the whole new document, `NO_CHANGE`, or `EMPTY`. Fact IDs, quotes, sources, `stale` and `unsupported` marks, and the `changes.jsonl` revision log are gone; the document keeps its previous version (`hermes telesec dossier show --previous`). `correct`, `pin`, `unpin`, `remove`, `changes`, `show --fact`, and `note --section` are removed: each prints a hint and exits with code 1. `note` no longer adds an owner fact to a section; each contact has one note: `--append` adds a paragraph, `--text` replaces the whole note, and `--text` needs `--replace` for a note converted from 0.14 or one over 500 characters. `export` now prints Markdown by default instead of JSON with the change log; `--format json` prints the stored document. To correct a dossier, add to its owner note: `hermes telesec dossier note --contact NAME --append "..."`. The note is the owner's own truth: the model follows it and never copies it, and a changed note rewrites the dossier on the next cycle. [Contact dossiers](docs/DOSSIERS.md).
- **Breaking:** `/dossier` in a Business chat now posts a fresh summary of the chat, titled "Summary of our chat" («Краткое содержание переписки»), with a footer that says it was prepared automatically and may contain mistakes. It is written at post time from the chat's live messages only: never from the private dossier, the owner note, the persona, or another chat, and never from deleted messages, replaced messages, or the text before an edit Telesec recorded (an edit it never saw, such as one made while history was off, leaves the older text in). If any of those messages is deleted or edited while the summary is written, nothing is posted. The command is deleted at once and the summary follows in the background (up to 5 minutes); it is posted only as a rich message, in the language of the summary. When nothing is posted, the owner's private chat with the bot says why, with new reasons for a contact who has not written in the last 24 hours, a chat with nothing to summarise, a summary already being prepared, messages that changed meanwhile, and a summary that could not be written (with a short code such as `timeout`). Any message from the contact counts for the 24 hours, including voice, photos, stickers, and files; the gateway remembers when the contact last wrote, in memory and without the content. `/dossier` is refused at once only when Telesec knows the contact has not written for 24 hours; otherwise it tries, and if Telegram refuses and Telesec saw no recent message from the contact, the owner gets the same reason. `preview --post` never gives that reason. A failed send now says "Telegram did not accept the summary". [`/dossier` in a chat](docs/DOSSIERS.md#dossier-in-a-chat).
- **Breaking:** dossiers use their own Hermes model task, `telesec_dossier` ("Telesec dossiers" in `hermes model`), instead of the voice-cleanup route. Its defaults are Vercel AI Gateway with `google/gemini-3.8-flash`, reasoning `low`, an 8,192-token output cap, and zero data retention. The plugin passes no provider or model, so no `plugins.entries.telesec.llm` trust config is needed; Hermes needs `AI_GATEWAY_API_KEY` for the `ai-gateway` provider. An install that used the default route moves from the native Gemini provider to Vercel AI Gateway → Google: a new processor of private chat text. The Settings confirmation, `hermes telesec settings set dossiers on`, `hermes telesec dossier enable`, and `status` name it. Choose another model with `hermes model` → Telesec dossiers, or `auxiliary.telesec_dossier` in `config.yaml`. `providerOptions` in the default `extra_body` is for `ai-gateway` only and stays under a model picked in `hermes model`, so for another provider set `auxiliary.telesec_dossier.extra_body` too, for example `{max_tokens: 8192}` for OpenRouter, or `{}` for the native `gemini` provider, which ignores both fields and has no output cap. Every call on the task, `/dossier` included, uses its `timeout` (120 seconds by default). `TELESEC_CLEANUP_PROVIDER` and `TELESEC_CLEANUP_MODEL` no longer route dossiers. If the dossier model fails, Hermes may retry with its fallback chain and then the main model; `status` shows which model answered last. [Model](docs/DOSSIERS.md#model).
- **Breaking:** `TELESEC_DOSSIER_PROVIDER` and `TELESEC_DOSSIER_MODEL` are deprecated. While `TELESEC_DOSSIER_PROVIDER` is set and the Hermes config names no `auxiliary.telesec_dossier.provider`, dossiers keep using that explicit route (with `TELESEC_DOSSIER_MODEL`, else `gemini-3.8-flash` for `gemini` or `google` and `google/gemini-3.8-flash` for any other provider), which still needs the trust config; `status` warns. This route and the direct `ai-gateway` call on a Hermes without plugin model tasks ask for a 16,384-token output cap with every call, as 0.14 did, which Hermes passes on to some providers, such as native `gemini`, but never to `ai-gateway`. They cannot ask for zero data retention. `status` shows both. `TELESEC_DOSSIER_MODEL` alone is ignored, and so are both once the Hermes config names a provider for the task. Remove them to use the task.
- **Breaking:** old dossiers are converted once, at the first dossier cycle, worker start, or `hermes telesec dossier` command. The owner's own text goes word for word into the owner note: notes and corrections as they were, pinned facts as `Keep: …` («Сохранить: …»), and the newest 20 removed or corrected texts as a `Leave out:` («Не включать:») paragraph; `note --text` does not replace this converted note without `--replace`. The model's active facts become the dossier at once, at revision 0, under the old section titles and never cut: the panel, `show`, and `export` show it in every chat, paused, inactive, and pruned ones included, and the first new pass rewrites it as its current version. `changes.jsonl` is deleted, and the old file is kept as `v1-dossier.json` until that dossier's first new pass or a forget. A file that can't be read is kept as `v1-dossier.json` until a forget, and `status` warns. A backup is never overwritten: a later `dossier.json` is converted again and kept as `v1-dossier.1.json`, `v1-dossier.2.json`, and so on. Stop a 0.14.0 gateway before running any `hermes telesec dossier` command of this version. To go back to 0.14.0: it finds no `dossier.json` and rebuilds dossiers from history at its own cost, and it ignores `document.json`; to keep the old owner edits, rename `v1-dossier.json` (or the newest numbered backup) back to `dossier.json` in each dossier directory before that dossier's first new pass. Its `dossier enable`, `dossier disable`, and Settings switch drop the new `gate` and `clairic` keys from `dossiers/settings.json`. [Upgrade and rollback](docs/DOSSIERS.md#upgrade-and-rollback).
- The owner persona is rebuilt from scratch from the owner's newest messages (up to 300 in the backfill window), at the first build once there are 10 and then at most weekly after 20 new ones; `run --persona` or a changed persona note rebuilds it now. Voice transcripts, including the later parts of a long transcript, are never part of it. Forgetting or erasing a chat that the persona or its previous version read resets the persona at once (its note stays), and the next cycle rebuilds it from the other chats.
- The panel's Dossier screen shows the document, one header line, the owner note («Ваша заметка (не публикуется)» in Russian), and one status line, with **Refresh**, **My persona**, and **Back**. Manage facts, fact cards, and Pin, Unpin, and Remove are gone; a button from an older panel message opens the dossier. **Refresh** with nothing new answers "Already up to date" without a model call.
- `hermes telesec dossier note` now writes the one owner note of a contact or the persona: `--append` adds a paragraph, `--text` replaces the whole note (`--replace` for a converted note or one over 500 characters), `--clear` deletes it, and without them it prints the note. `preview` now prints the system prompt and the user input as `--- system ---` and `--- user ---` blocks instead of bare JSON, and `preview --persona` says whether the next cycle would rebuild the persona. Add `show --previous`, `preview --post` (the exact input of the next `/dossier` summary), `gate`, and `clairic`. `gate auto` and `clairic on` keep the setting when they cannot run yet and say why. `status` shows the model in effect with its reasoning, output cap, and data retention, the model that answered last (flagged when the host fell back to another model), the message check and fact extraction, and model calls, tokens, and estimated cost per month. It warns about task settings that undo the defaults: following the main model (`auto`), a reasoning level other than `low`, an `extra_body` without the output cap or zero data retention, or the gateway-only `providerOptions` on another provider, which Settings also shows under the dossier model.
- Add an optional message check, off by default: `hermes telesec dossier gate auto`. Before a routine refresh, TypeSafe Jev (`typesafe-ai/jev-1.13.0`) reads the current dossier and the new messages through the same Vercel AI Gateway, with zero data retention, and the refresh waits when they add nothing new. It never drops messages: the next message, or 72 hours, brings them back. It runs only with `AI_GATEWAY_API_KEY` and the dossier model on the gateway, and never for edits, deletions, a changed note, a first build, Refresh, the persona, or `/dossier`. It reads the key and `AI_GATEWAY_BASE_URL` from the active Hermes profile. While it runs, turning dossiers on says that the current dossier and new messages go to TypeSafe. Turning it off, or turning dossiers or history off, stops its requests at once, also inside a running cycle. [Message check](docs/DOSSIERS.md#message-check).
- Add optional fact extraction, off by default: `hermes telesec dossier clairic on`. New messages of a contact refresh also go to Cloudflare Workers AI (Clairic, a preview model), which picks out dates, amounts, and contact details as hints for the writer. It needs `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` and never runs for the persona or `/dossier`. While it runs, turning dossiers on names Cloudflare as one more processor. Turning it off stops its requests at once, also inside a running cycle. `preview` says when it would run, but cannot show its hints. It has not been measured yet. [Fact extraction](docs/DOSSIERS.md#fact-extraction).
- A model answer must end with an end marker, so a cut-off or refused answer changes nothing. Inline reasoning such as `<think>…</think>` is dropped first, and an answer with an unclosed reasoning block changes nothing either. A document over the size limit gets one call to shorten it, which takes its own place in the per-minute call limit. A contact that fails 3 times in a row waits 1, 2, 4, and up to 24 hours, then tries again on its next chat change; Refresh tries at once. History pruned by retention is never treated as deleted and costs no model call.
- The `dossiers` skill now covers reading, the owner note, Refresh, and forget, and tells the agent never to quote a private dossier, owner note, or persona into a Business chat.
- `scripts/render-dossier-screenshots.py` writes the exact rich message HTML of the Dossier screen and the `/dossier` summary over a fictional contact to `docs/images/src/` for real Telegram screenshots. The old dossier screenshots are removed.
- `tests/dossier_eval/` runs a paid, opt-in quality and cost comparison of the old and new dossiers on made-up chats. The transcript of a deleted voice message is counted but is not a release blocker, because it stays in the chat. The offline test of the old-dossier arm runs only when `TELESEC_EVAL_V1_WORKTREE` names a `v0.13.0` worktree. [Contributing](CONTRIBUTING.md#dossier-eval).

## 0.14.0 - 2026-10-20

- **Breaking:** `TELESEC_HISTORY_CONNECTIONS`, `TELESEC_HISTORY_CHATS`, and `TELESEC_HISTORY_CHAT_TYPES` no longer choose the recorded chats on their own. On the first start with any of them set to a value, the plugin keeps the old filter as a stored rule: it saves the filter as 0.13 read it under `legacy_scope` in `chat-settings.json` and records the run there with counts only. The rule still applies per connection and chat, so a chat it kept out, new chats included, saves no history and its dossier and persona use pause; a value that matched nothing before still matches nothing, and an empty variable is still no filter. Until the rule is stored, the variables keep applying and the next start retries. While they stay set they apply too, so a chat is kept out when the rule or the variables keep it out. Telesec 0.13 and older read only the variables, so keep them set while you may go back, and remove them after that; each start warns once for every variable still set. Going back can undo **Save history** for a chat the rule keeps out, because 0.13 deletes a chat's entry when it changes that chat and no "off" is left. Repairing a corrupt `chat-settings.json` with `chat set ... --owner` keeps the rule from the damaged file, stores it again from the variables, or says it was lost. Group chats are never recorded. [Moving from the history environment variables](README.md#moving-from-the-history-environment-variables).
- A chat the old server scope keeps out on every connection it records through shows **Don't save** with "•" and the line `History: off by the old server scope` («История: выключена старой настройкой сервера») in its owner panel. **Save history** or `hermes telesec chat set <chat> --history on` turns it on with a stored "on" that overrides the rule and the variables. The old `History: off (server settings)` line is gone, and `chat get` and `chat list` show the state `scope` instead of `server`.
- Add `hermes telesec chat scope`, which shows the stored old server scope rule and the variables in effect with counts only, and `hermes telesec chat scope clear --yes`, which drops the stored rule: chats it kept out start saving history with their next message, except chats set to Don't save and chats the variables keep out while set. A later start never stores the variables as the rule again. `chat list`, `chat get` (JSON: `old_scope` with `stored` and `variables`), and `hermes telesec settings` say when the rule applies.
- Add **🗑 Erase saved history** («🗑 Стереть сохранённую историю») to a chat's owner panel when history holds messages from the chat and the chat saves nothing now: it is set to Don't save, the old server scope keeps it out, or history is off in Settings (then the button shows under the `History: off in Settings` line). It asks first in the same message, stops a running dossier refresh, deletes the chat's saved history on the owner's connection, its contact-catalog entry, and pending deletion classification, and then its dossier. The chat keeps its setting, and stats show no history for it. It refuses while the chat saves history or while chat settings can't be read, so a stale or repeated tap erases nothing, and another owner's chat with the same contact is never touched. Once the chat's history is deleted, its dossier is always forgotten, even when the contact catalog can't be updated. [Erase one chat](docs/HISTORY.md#erase-one-chat).
- Add `hermes telesec history forget --chat <chat>` (same selectors as `history show`) and `hermes telesec history forget --all --yes`. Without `--yes` it prints what it would erase and exits with code 1. `--all` also forgets every dossier and the owner persona.
- `hermes telesec history import` refuses a chat the old server scope keeps out and names `hermes telesec chat set <chat> --history on`. It and `history forget` find the chat's owner as `chat set` does, so a chat turned on with `chat set ... --owner` counts as on.
- `hermes telesec history stats` no longer prints `connections=`, `chats=`, or `chat_types=`.
- The stats heat map of the period starts where history starts, so the days before it are no longer shown as `·`, days without messages. An imported message from before the first capture still counts as history. In the example in [owner panel stats](docs/STATS.md#in-telegram-owner-panel), the calendar no longer shows its first two weeks as empty.

## 0.13.0 - 2026-10-20

- Add `hermes telesec history import <result.json> --chat <id> [--connection <id>] [--dry-run]`. It imports the earlier text messages of one private chat from a Telegram Desktop export ("Export chat history", JSON), so stats, the 📊 panel, history search, and new dossiers see the time before capture started. Only messages older than the chat's first captured record are imported, and a message already in history is never added again, so re-running is safe. Voice messages, round videos, audio, other media, service messages, the owner's `/stats` and `/dossier`, and a bot's posts are skipped and counted in the summary; nothing is transcribed. Imported records carry `"source":"import"` and live in the chat's normal monthly files. The command refuses while history is off or the chat is set to Don't save, and skips messages older than the retention period. [Import past messages](docs/HISTORY.md#import-past-messages).
- Add history retention to Settings: a **Forever · 1 year · 90 days · 30 days** row under the history row («Всегда · 1 год · 90 дней · 30 дней» in Russian), with "•" on the value in effect and a `Keep history: …` line that stays readable on a narrow screen. A shorter time asks first and says what goes: history is deleted a whole month at a time, at the next cleanup once all of a month is older than the chosen time. Cleanup runs when the gateway starts, when a `hermes` command loads Telesec, and at most hourly while Business messages arrive. A longer time applies at once. The row stays while history is off, because cleanup keeps running. Only an owner of every Business connection the bot knows about can change it; another verified owner sees it read-only. Maintenance reads the stored value on every run, so a change from Telegram or the CLI needs no restart.
- Add `hermes telesec settings set retention <forever|365|90|30|N>`. `hermes telesec settings` shows the retention, and its JSON has `retention.days` (`0` is forever) with its source. It is stored as `retention` in `data/telesec/settings.json`.
- Remove `TELESEC_HISTORY_RETENTION_DAYS`. On the first start a value other than `0` is stored once as the retention (`via migration`) and logged; after that the variable is not read, and each start logs one warning while it is set. A `settings set` that starts a new or repaired `settings.json` stores retention as forever, so a leftover variable cannot shorten it again; only a deleted file followed by a start with the variable moves it in again. A value outside the four choices shows as its own button (for example `• 45 days`) until changed. Telesec 0.12 ignores the stored retention, so after going back to it the variable applies again. `TELESEC_HISTORY_MAX_BYTES` stays an environment variable: a disk-safety limit for operators.
- Settings shows the models in use, read-only: `Dossier model: <provider / model>` and `Voice cleanup: <provider / model>` or `off` («Модель досье», «Очистка расшифровок»). They are the same names `hermes telesec dossier status` shows and the cleanup calls. User names, passwords, queries, and fragments in a URL are never shown.
- Redesign the 📊 Stats view in the owner panel and the `/stats` card as Telegram rich messages. One balance bar of 10 squares replaces the two share bars, with the contact always 🟦 and the owner always 🟩. Each side's numbers are in a table. Emoji heat maps (`·` 🟨 🟧 🟥) of the period, weekdays, and hours sit in table cells, so the columns line up in any font: a calendar for days, then for longer periods a row of weeks per month, a row of months or quarters per year, or the years. There are no code blocks or copy bars. The footer is short: when history starts and `text only`, with no clock time or time zone, and the deletions not in history and edits without original stay in the CLI. Durations read `12 min` and `1 h 40 min`, and Russian decimals use a comma. Contact names are cut to 16 characters in the tables. A view Telegram does not take falls back to a short plain-text version.
- `/stats` edits the command into the rich card. When the edit fails, the bot sends the card with `sendRichMessage`, then a plain-text card if Telegram rejects that too, and deletes the command. A timed-out rich send gets no plain-text card, so the contact never sees two cards.
- `scripts/render-stats-screenshots.py` now writes the exact rich message HTML of each view to `docs/images/src/` for real Telegram screenshots, and no longer renders PNG mockups. The `docs/images/stats-panel-*.png` and `stats-card-*.png` files are now real Telegram screenshots of that HTML over fictional history, and the README shows the card too.

## 0.12.2 - 2026-10-20

- Transcribe Business voice messages, round videos, and audio from every contact, with no variable. The ordinary DM allowlist no longer applies to Business media; per-chat modes and Settings decide what is transcribed. `TELESEC_VOICE_BYPASS_AUTH` is removed and ignored.
- Add conversation metrics to `stats`: each side's share, turns and messages per turn, reply times with median and p90 ([#28](https://github.com/neoromantic/telesec/issues/28)), who is waiting for a reply, median message length, edits, messages per hour and weekday with the peak, activity over the range, streaks, the longest silence, and a comparison with the previous period of the same length when retained history covers it (as many whole days when the range starts at midnight). JSON `schema_version` is now 2; the new keys come after `missing_history`, and the existing keys are unchanged. Message text is read only to count its characters.
- Remove `TELESEC_TIMEZONE` and the plugin's `timezone` setting: stats use the Hermes time zone (`HERMES_TIMEZONE` or `timezone` in `config.yaml`), else UTC, and `--tz` still overrides it in the CLI.
- Redesign the 📊 Stats view in the owner panel as a compact Telegram HTML report for a phone screen: share bars, a per-side table (messages, reply median and p90, messages per turn, length, edits), who is waiting for a reply, the peak, sparklines for hours, weekdays, and activity, streaks, the longest pause, sessions, deletions, the change against the previous period, and what history is missing. The bars and table share one monospace block, and the sparklines and summary another, so Telegram shows two copy bars, not four. It is in Russian for a Russian Telegram app and in English otherwise, period buttons, error states, and the paused-history line included. In a chat set to Don't save, the report still shows what was saved, with that line last; the `/stats` card shows no such line. Periods are now whole local days with today, so `7d` shows 7 days instead of 7 × 24 hours over 8 dates. An empty period now shows one line instead of zeros. Link previews are off, and contact names are escaped and cut to 64 characters in the title and 8 columns in the monospace blocks (wide CJK and emoji characters count two, so columns stay aligned). Names with right-to-left letters are wrapped in left-to-right marks, so they cannot flip a line. [Owner panel stats](docs/STATS.md#in-telegram-owner-panel).
- Add `PanelView.parse_mode` and `PanelView.disable_link_preview` for panel sections that send formatted text. Plain sections are sent as before, and a formatted view Telegram rejects falls back to the plain "Section unavailable" text.
- Add `stats_render.card`, a shareable stats card for two people without owner-only details (deletions, edits, waiting, missing history, p90).
- Add the owner-only in-chat `/stats [7d|30d|90d|all]` command, one of the two owner commands typed in a Business chat (with `/dossier`). `/stats` alone means all history. The bot edits the command in place into the stats card (Telegram HTML, link previews off), in Russian or English by the owner's Telegram app; the contact sees the card too. If the edit fails, the bot sends the card and deletes the command; if the owner already deleted the command, nothing is posted. With history off, no history for the chat, or a read error, the command becomes a short notice without details that is deleted about 5 seconds later. The command, the card, a fallback card or notice, their edit echoes, and their deletion are never recorded in history or counted (message IDs are kept in memory for 24 hours; a fallback whose send timed out is recognized by its text for 10 minutes, and such a notice is still deleted). A contact's, forwarded, inline-bot, edited, or bot-sent `/stats` and an unknown argument stay ordinary text. [In-chat `/stats`](docs/STATS.md#in-a-business-chat-stats).
- Add synthetic screenshots of the 📊 Stats panel view and the `/stats` card in English and Russian (`docs/images/stats-*.png`), made from fictional history by the real views. `scripts/render-stats-screenshots.py` rebuilds them and their HTML sources. In the README, the English panel screenshot replaces the real screenshot of the old plain-text Stats view.

## 0.12.0 - 2026-10-20

- Add Settings: one screen in the owner's private chat with the bot that turns transcription, history, and dossiers on or off for all chats. Open it with `/telesec` or the new ⚙️ Settings button on every chat's panel. Turning dossiers on asks first and names the model; while history is off, dossiers are paused and Settings says so. Only an owner of every Business connection the bot knows about can change the switches; another verified owner sees them read-only. Nothing is posted into a Business chat, and a `/telesec` typed in a Business chat is never answered there.
- Add `hermes telesec settings [--format json]` and `hermes telesec settings set <transcription|history|dossiers> on|off`. Changes apply to the next update with no restart. `hermes telesec dossier enable|disable` still works.
- Store transcription and history in `data/telesec/settings.json` (private, atomic writes). A corrupt file keeps the last valid switches; only `settings set` backs it up and replaces it.
- Remove `TELESEC_DISABLE`, `TELESEC_HISTORY_ENABLE`, and the Desktop `history_enable` setting. On first start, a value that differs from the default is stored once (`via migration`) and logged, so a gateway with history on keeps it on with no manual step. A `TELESEC_HISTORY_ENABLE=0` that overrides a Desktop `history_enable` is stored as history off, so a later run without the variable cannot turn history on. After that the old names are ignored with one warning per start. A CLI run without the gateway's environment can store only the Desktop setting's value.
- Going back to 0.11.0 or older ignores `data/telesec/settings.json`, so transcription and history follow the environment variables and the Desktop setting again. Keep them until you no longer plan to go back.
- Add per-chat history and dossier controls to the owner panel (Manage Bot), in the same style as transcription modes: **Save history** / **Don't save** and **Keep dossier** / **No dossier**, with "•" on the value in effect. A row that cannot apply is hidden, and a short line says why (off in Settings, off by server settings, needs history; group chats have no dossier row). Don't save stops recording the chat's new messages, edits, and deletions and pauses its dossier. No dossier keeps history but skips the chat in dossier cycles and the persona, stops a running panel Refresh, and makes `/dossier`, `dossier run --contact`, and `dossier preview` refuse with "Dossier is off for this chat." Off is not delete: saved history stays (retention still prunes it), and a paused dossier stays frozen and viewable. Reset stays transcription-only. The Stats section says when history is paused for the chat.
- Add `hermes telesec chat list|get|set [--history on|off] [--dossier on|off]` with the same chat selectors and owner rules as `mode`. In JSON, `mode list` and `mode get` also report `effective_history` and `effective_dossier`, and `hermes telesec settings` counts chats with history or the dossier off. The agent's command reference names `chat get` and `chat set`.
- Store per-chat switches in `data/telesec/chat-settings.json`: per owner and chat, only "off" values, private atomic writes, no message text. The checks fail closed: a chat id that some owner paused is skipped while the owner of another connection is unknown, and a file that was never readable pauses history and dossiers for every chat until `hermes telesec chat set ... --owner ID` backs it up and starts a new one. A corrupt file keeps the values last read, and Telegram never overwrites it. Telesec 0.11.0 and older ignore this file, so after a downgrade those chats are recorded again.
- A chat that the server's history settings (`TELESEC_HISTORY_CONNECTIONS`, `TELESEC_HISTORY_CHATS`, `TELESEC_HISTORY_CHAT_TYPES`) leave out gets no dossier work either; its stored dossier stays.
- `mode` and `chat` store a numeric chat id as Telegram sends it, so `0991` means chat `991`.
- Panel section buttons and Refresh now go two per row, and the Stats button has a Russian label.
- Move the dossier on/off switch from the Dossier section to Settings. Old Enable and Disable buttons now just show the dossier.
- Dossiers pause while history is off: the worker runs no cycle and `hermes telesec dossier run` and `status` say why.
